# 迭代二：文件引擎 + 真实 Handler + 推荐 + 调度

**目标**：将占位 handler 替换为真实文件读写，实现推荐引擎和定时调度器，让 Bot 能够真正"记住"和"主动服务"。

**前置条件**：迭代一完成（QQ 收发 + NL 解析链路已跑通）

---

## 迭代二 vs 迭代一 对比

| | 迭代一 | 迭代二 |
|------|------|------|
| handler | 全部返回 AI 的 responseHint 或占位文案 | 真实读写 data/ 目录下 .md 文件 |
| 数据存储 | 无 | 文件系统（data/{userId}/ 目录树） |
| 内存索引 | 无 | 启动扫描 + 运行时双写 |
| 推荐 | 占位文案 | 场景映射 + 兴趣打分 + 去重 |
| 定时调度 | 无 | 提醒 + 重复任务 + 过期检测 + 每日汇总 |
| 消息模板 | 占位 | 结构化模板（推荐列表、每日汇总等） |

## 子任务拆分

### 任务 1：数据层 — 文件引擎 + Markdown 解析/写入

**文件：** `src/data/index-types.ts`、`src/data/markdown-parser.ts`、`src/data/markdown-writer.ts`、`src/data/file-engine.ts`

#### 1.1 `index-types.ts` — 类型定义

```typescript
interface EntryIndex {
  id: string;                    // 编号：a1b2c3d4
  title: string;                 // 条目标题
  url: string | null;
  statusChar: ' ' | 'x' | '-' | '~' | '?';
  customStatus: string;          // H2 标题（"想看"、"在看"…）
  interest: number;              // 0-100
  deadline: string | null;       // ISO datetime
  remindAt: string | null;
  repeatRule: string | null;
  importance: '高' | '中' | '低' | null;
  progress: string | null;
  reason: string | null;
  note: string | null;
  folderPath: string;            // "娱乐/综艺"
  fileName: string;              // "综艺.md"
  lineNumber: number;
  section: string;               // H2 标题
  reminded: boolean;
  createdAt: string;
  updatedAt: string;
}

interface GlobalIndex {
  entries: Map<string, EntryIndex>;         // id → EntryIndex
  byFolder: Map<string, EntryIndex[]>;       // folderPath → entries
  byFile: Map<string, EntryIndex[]>;         // "娱乐/综艺.md" → entries
  reminders: EntryIndex[];                   // 待提醒条目
  folderTree: TreeNode[];                    // 目录树
}
```

#### 1.2 `markdown-parser.ts` — 解析单个 .md 文件

```
输入：文件内容字符串 + folderPath + fileName
输出：EntryIndex[]
```

解析规则：
- `# 标题` → 文件名确认
- `## 标题` → section（如"想看"、"🔴 重要紧急"）
- `- [x] 条目内容  编号：xx  兴趣：高` → EntryIndex
- 从行内提取字段：`编号：`、`兴趣：`、`截止：`、`提醒：`、`重复：`、`进度：`、`备注：`、`原因：`、`重要性：`、`创建：`、`更新：`
- 链接提取：`[标题](url)` → title + url

#### 1.3 `markdown-writer.ts` — 写入条目到 .md 文件

```
核心方法：
  appendEntry(filePath, section, entry): void   // 追加到指定 H2 节下
  moveEntry(filePath, entry, newSection): void  // 移动到新 H2 节
  removeEntry(filePath, entry): void            // 删除条目行
  updateEntryLine(filePath, entry): void        // 原地更新条目行
  ensureSection(filePath, section): void        // 确保 H2 节存在
```

写入规则：
- 条目格式：`- [状态符] [标题](url)  编号：xx  字段：值  …`
- 字段只在有值时输出，null 不输出
- 每次写入自动追加 `更新：YYYY-MM-DD`
- H2 节按顺序排列：先"想看/要做"等默认节，再"已看/已完成"等终态节

#### 1.4 `file-engine.ts` — 文件引擎核心

```
核心方法：
  init(userId): void                          // 启动时扫描 data/{userId}/ → 构建 GlobalIndex
  scanAll(userId): GlobalIndex                // 全量扫描
  ensureFolder(userId, folderPath): void      // 确保目录存在（含 README.md）
  findEntry(userId, query): EntryIndex | null // 按编号/标题查找
  searchEntries(userId, query): EntryIndex[]  // 模糊搜索多条
  addEntry(userId, folderPath, fileName, section, entry): EntryIndex
  updateEntry(userId, id, changes): EntryIndex
  deleteEntry(userId, id): void
  getReminders(userId): EntryIndex[]
  getByFolder(userId, folderPath): EntryIndex[]
```

双写策略：
1. 先写 .md 文件（真相源）
2. 成功后再更新内存索引
3. 文件写入失败 → 不更新索引，返回错误

目录自动创建：
- AI 指定 `folderPath="美食/菜谱"` → 自动创建 `data/{userId}/美食/` 和 `data/{userId}/美食/菜谱/`
- 新建文件夹时自动生成 README.md（含分类说明）
- 新建 .md 文件时自动写入 `# 标题` 行

### 任务 2：Handler 层 — 真实实现

**文件：** `src/handlers/create-handler.ts`、`query-handler.ts`、`update-handler.ts`、`delete-handler.ts`、`recommend-handler.ts`、`feedback-handler.ts`

#### 2.1 `create-handler.ts`

```
输入：NlParseResult + userId
流程：
  1. ensureFolder(userId, folderPath)     // 确保目录存在
  2. 生成条目 ID（短 UUID 8 位）
  3. 组装 EntryIndex（statusChar 根据 status 字段推断）
  4. addEntry() → 写入 .md + 更新索引
  5. 返回 responseHint
```

#### 2.2 `query-handler.ts`

```
输入：NlParseResult + userId
流程：
  1. 按 folderPath / fileName 定位文件
  2. 如果 target.title 存在 → 模糊匹配单条
  3. 否则 → 列出该文件下所有条目
  4. 格式化返回（列表 or 单条详情）
```

#### 2.3 `update-handler.ts`

```
输入：NlParseResult + userId
流程：
  1. 按 target.title 模糊查找条目
  2. 更新字段：newStatus → 改变 statusChar + 移动 H2 节
  3. 如果有 interestDelta → 调用 interest-manager
  4. updateEntry() → 原地修改行 or 移动行
```

#### 2.4 `delete-handler.ts`

```
输入：NlParseResult + userId
流程：
  1. 按 target.title 查找条目
  2. 确认删除（目前直接删除，后续可加确认流程）
  3. deleteEntry() → 从 .md 移除行 + 从索引移除
```

#### 2.5 `recommend-handler.ts`

```
输入：NlParseResult + userId
流程：
  1. 根据 scene 确定候选文件夹（SCENE_FOLDERS 映射）
  2. 调用推荐引擎打分排序
  3. 去重（30 分钟内推荐过的跳过）
  4. 取 top 3
  5. 用 message-builder 构建回复
```

#### 2.6 `feedback-handler.ts`

```
输入：NlParseResult + userId
流程：
  1. 按 target.title 模糊查找条目
  2. 如果有 interestDelta → 调用 interest-manager 调整
  3. 如果有 newStatus → 更新条目状态
```

### 任务 3：推荐引擎

**文件：** `src/recommend/engine.ts`、`src/recommend/interest-manager.ts`

#### 3.1 `engine.ts` — 推荐引擎

**场景 → 文件夹映射：**

```typescript
const SCENE_FOLDERS: Record<string, string[]> = {
  boredom: ['娱乐'],
  hungry:  ['美食'],
  learn:   ['学习', '工作'],
};
```

**打分公式：** `score = interest * 0.6 + freshness * 0.2 + variety * 0.2`

| 因子 | 计算方式 | 权重 |
|------|---------|:----:|
| interest | 条目兴趣度 / 100 | 0.6 |
| freshness | 1 - (距今天数 / 30)，新条目更优先 | 0.2 |
| variety | 上次推荐距今 > 30min → 1，否则 → 0 | 0.2 |

**过滤规则：**
- statusChar 为 `x`（已完成）/ `-`（搁置）→ 不推荐
- interest < 30 → 不推荐
- 30 分钟内已推荐 → 不推荐

**核心方法：**
```typescript
recommend(userId: string, scene: string, count: number): RecommendResult[]
recordRecommended(userId: string, entryId: string): void  // 记录已推荐
```

#### 3.2 `interest-manager.ts` — 兴趣权重

| 触发事件 | delta | 说明 |
|---------|:-----:|------|
| 新建条目 | 初始 60 | 用户说"帮我记 xxx"，默认兴趣度 |
| 用户喜欢（"不错"、"好看"） | +25 | 显式正面反馈 |
| 用户不喜欢（"不想看"） | -40 | 显式负面反馈 |
| 已消费（"看完了"） | -80 | 看完/吃完后大幅降低 |
| 想多看同类 | +15 | 连带提升同文件其他条目 |
| 每日衰减 | -1/天 | 超过 30 天无交互后开始 |

### 任务 4：定时调度器

**文件：** `src/scheduler/scheduler.ts`、`reminder.ts`、`recurring.ts`、`expiry.ts`、`decay.ts`、`daily-summary.ts`

#### 4.1 `scheduler.ts` — 调度主循环

```typescript
class Scheduler {
  private timers: NodeJS.Timeout[] = [];

  start(userId: string, sendFn: SendFunction): void {
    this.timers.push(setInterval(() => checkReminders(userId, sendFn), 15_000));
    this.timers.push(setInterval(() => checkRecurring(userId, sendFn), 300_000));
    this.timers.push(setInterval(() => checkExpiry(userId, sendFn), 3_600_000));
    this.timers.push(setInterval(() => applyDecay(userId), 86_400_000));
    // cron 09:00 每日汇总
  }

  stop(): void { /* clear all timers */ }
}
```

#### 4.2 `reminder.ts` — 提醒检查（15s）

```
遍历 index.reminders
  → remindAt <= now() AND !reminded
    → sendMessage("⏰ {remindAtDescription}：{title}")
    → 标记 reminded = true
    → 更新 .md 文件 + 索引
    → 如果有 repeatRule → 计算下一次 remindAt，重置 reminded
```

#### 4.3 `recurring.ts` — 重复任务（5min）

```
遍历所有有 repeatRule 的条目
  → 当前时间匹配重复规则？
    → 计算下一次 remindAt
    → 更新 .md 文件 + 索引
```

支持的重复规则格式：
- `每天 09:00`
- `每周五 14:00`
- `每月1日 09:00`
- `每周一、周三、周五 10:00`

#### 4.4 `expiry.ts` — 过期检测（1h）

```
遍历所有有 deadline 的条目
  → deadline < now() AND statusChar 不是终态
    → sendMessage("「{title}」过了 {n} 天，还需要做吗？")
```

#### 4.5 `decay.ts` — 兴趣衰减（24h）

```
遍历所有条目
  → updatedAt > 30 天前 AND interest > 0
    → interest -= 1
    → 更新索引
    → 暂不写回 .md（减少 I/O，下次手动更新时一起写回）
```

#### 4.6 `daily-summary.ts` — 每日汇总（09:00）

```
cron "0 9 * * *"
  → 收集当日待办（deadline 在今天）
  → 收集过期未处理任务
  → 用 message-builder 构建汇总消息
  → sendMessage 推送
```

## 数据流（以"帮我记 runningman"为例）

```
用户发送 "runningman 这个综艺不错，帮我记一下"
  │
  ▼
preClassify() → hint: { intent: "create" }
  │
  ▼
parseNL() → NlParseResult {
  intent: "create",
  folderPath: "娱乐/综艺",
  fileName: "综艺",
  entry: { title: "Running Man", interest: 80, status: "想看" }
}
  │
  ▼
create-handler.ts:
  1. fileEngine.ensureFolder(userId, "娱乐/综艺")
     → data/1002739223/娱乐/ 已存在，跳过
     → data/1002739223/娱乐/综艺.md 不存在 → 创建，写入 "# 综艺\n\n## 想看\n\n"
  2. 生成 ID: "a1b2c3d4"
  3. 添加条目行:
     → markdown-writer.appendEntry()
     → 写入: `- [ ] [Running Man]  编号：a1b2c3d4  兴趣：80  创建：2026-05-28`
  4. 更新内存索引
  5. 返回 reply
  │
  ▼
sendMessage("已记到综艺清单 ✅")
```

## 验收标准

### Handler 验收
- [ ] 发送"帮我记 runningman，链接是 xxx" → data/{userId}/娱乐/综艺.md 中出现对应条目
- [ ] 发送"我追的综艺有哪些" → 正确列出综艺.md 中所有条目
- [ ] 发送"runningman 看完了" → 条目状态变为 [x]，移到"已看"节下
- [ ] 发送"删掉 runningman" → 条目从文件中移除
- [ ] 发送"好无聊" → 推荐娱乐分类下 3 个条目（如存在）
- [ ] 发送"最近不想看 runningman" → 条目兴趣度降低

### 推荐引擎验收
- [ ] 已看/搁置的条目不出现在推荐中
- [ ] 高兴趣度条目排在前面
- [ ] 30 分钟内推荐过的条目不出现在新一轮推荐中

### 调度器验收
- [ ] 设置提醒的条目在到期时收到提醒消息
- [ ] 重复任务（如"每周五交周报"）自动生成下一次提醒
- [ ] 过期任务收到主动询问
- [ ] 每日 09:00 收到当日汇总
