# QQ 个人管家 Bot 架构设计

## 核心设计

核心原则：极端用户友好

- 文件夹系统即树状数据结构
- markdown 即数据表

**示例目录结构：**

```
data/
├── 娱乐/
│   ├── README.md      ← 分类说明（skill 文档）
│   ├── 综艺.md
│   ├── 电影.md
│   ├── 小说.md
│   └── 游戏.md
├── 美食/
│   ├── README.md
│   ├── 想吃的餐厅.md
│   └── 菜谱.md
├── 工作/
│   ├── README.md
│   ├── 日程表.md
│   └── 密码箱.md
└── 学习/
    ├── README.md
    └── 想学的技能.md
```

**路径即为分类：** `data/娱乐/综艺.md` → 分类路径 = `娱乐/综艺`

**AI 自动建文件夹和文件：** 用户说"帮我记个菜谱，宫保鸡丁的做法"，AI 判断这属于"美食/菜谱"，自动创建 `data/美食/菜谱.md`（如果不存在），然后写入条目。AI 创建新分类时也会自动生成对应的 `README.md`。

### Markdown 文件格式

每个 `.md` 文件就是一张表。文件名（不含 `.md`）即为表名。条目以 `字段：值` 格式附加元数据，用两个空格与内容分隔：

```
- [状态] 条目内容  字段：值  字段：值
```

**支持的字段：**

| 字段 | 值示例 | 说明 |
|------|--------|------|
| `编号` | `a1b2` | 系统分配，唯一定位条目 |
| `兴趣` | `高` `中` `低` | 兴趣温度 |
| `截止` | `2026-05-29 15:00` | 截止时间 |
| `提醒` | `提前5分钟` `2026-05-29 14:55` | 提醒时间 |
| `重复` | `每周五 14:00` `每天 09:00` `每月1日 09:00` | 重复规则 |
| `进度` | `S3` `80%` | 进度描述 |
| `备注` | `朋友推荐的这个` | 备注信息 |
| `原因` | `最近不想看` | 搁置/跳过原因 |
| `重要性` | `高` `中` `低` | 四象限排序 |
| `创建` | `2026-05-28` | 创建时间（系统写入） |
| `更新` | `2026-05-28` | 更新时间（系统写入） |

**状态符号：**

| 符号 | 含义 |
|------|------|
| `[ ]` | 待办 / 想看 / 想去 / 默认 |
| `[x]` | 已完成 / 已看 / 已买 |
| `[-]` | 搁置 / 废弃 / 不想看了 |
| `[~]` | 进行中 / 在看 / 学习中 |
| `[?]` | 待确认 |

**完整文件示例：**

```markdown
# 综艺

## 想看
- [ ] [Running Man](https://xxx)  编号：rm-001  兴趣：高  创建：2026-05-20

## 在看
- [~] 极限挑战  编号：jx-001  进度：S3  兴趣：高

## 已看
- [x] 跑男第一季  编号：pn-001
- [-] 某某综艺  编号：mm-001  原因：最近不想看  兴趣：低
```

```markdown
# 日程表

## 🔴 重要紧急
- [ ] 开会讨论方案  编号：sch-001  截止：2026-05-29 15:00  提醒：提前5分钟

## 🟡 重要不紧急
- [ ] 每周五交周报  编号：sch-002  重复：每周五 14:00

## 🔵 不重要紧急
- [ ] 回复张三消息

## ⚪ 不重要不紧急
- [ ] 看看新出的工具  兴趣：低
```

### 内存索引

启动时全量扫描 `data/` 目录下所有 `.md` 文件，解析为内存数据结构，用于快速查询：

```typescript
interface EntryIndex {
  id: string;
  title: string;
  url: string | null;
  statusChar: ' ' | 'x' | '-' | '~' | '?';
  customStatus: string;       // 从 H2 标题推断（"想看"、"在看"…）
  interest: number;           // 0-100
  deadline: string | null;    // ISO datetime
  remindAt: string | null;
  repeatRule: string | null;
  importance: '高' | '中' | '低' | null;
  progress: string | null;
  reason: string | null;
  note: string | null;
  // 文件系统定位
  folderPath: string;         // "娱乐/综艺"（相对于 data/ 的目录路径）
  fileName: string;           // "综艺.md"
  lineNumber: number;
  section: string;            // H2 标题（"想看"、"🔴 重要紧急"…）
  reminded: boolean;
  createdAt: string;
  updatedAt: string;
}

// 全局索引
const index = {
  entries: Map<string, EntryIndex>,           // id → EntryIndex
  byFolder: Map<string, EntryIndex[]>,         // folderPath → entries
  byFile: Map<string, EntryIndex[]>,           // "娱乐/综艺.md" → entries
  reminders: EntryIndex[],                     // 有 remindAt 且未提醒的条目
  folderTree: TreeNode[],                      // 文件夹树结构
};
```

**同步策略：**
- 启动时：全量扫描 → 构建内存索引
- 写入时：先写 `.md` 文件 → 再更新内存索引（双写，文件是真相源）
- 外部修改：chokidar 监控文件变更 → 重解析变更文件 → 更新内存索引（阶段三）

### 条目标识

- 系统创建：自动分配短编号写入 `编号：`（如 `编号：a1b2c3d4`）
- 用户手动添加（无 `编号：`）：以标题 hash 作为 ID
- 更新/删除时：先按 `编号：` 精确匹配，无则按标题模糊匹配

### 分类树

分类树完全由文件系统目录结构表达，不需要单独维护：
- 每个文件夹 = 一个分类节点
- 每个 `.md` 文件 = 叶子节点（表）
- 树结构在启动扫描时自动构建
- AI 创建条目时若目标目录不存在 → 自动 `mkdir` 创建

```
data/
├── 娱乐/           ← 一级分类
│   ├── 综艺.md     ← 表（叶子）
│   ├── 电影.md
│   └── 游戏.md
├── 美食/           ← 一级分类
│   ├── 想吃的餐厅.md
│   └── 菜谱.md
└── 工作/           ← 一级分类
    ├── 日程表.md
    └── 密码箱.md
```

### README.md — 分类说明文档

每个分类文件夹下都有一个 `README.md`，描述该分类的用途和内容，相当于文件夹的"skill 说明"。AI 在归类决策时会读取这些文档来理解分类语义。

**示例 `data/娱乐/README.md`：**

```markdown
# 娱乐

记录娱乐消遣相关的内容，帮助用户在无聊时找到想做的事。

## 包含的表
- 综艺 — 追的、想看的、已弃的综艺节目
- 电影 — 想看的电影、看过的评价
- 小说 — 在追的、已完结的小说
- 游戏 — 想玩、在玩、已通关的游戏

## 典型交互
- "帮我记一下 runningman，链接是 xxx" → 新增到综艺表
- "好无聊，不知道干嘛" → 从娱乐分类推荐内容
- "xxx 看完了" → 标记为已看，降低推荐权重
```

**作用：**
- **给 AI 看** — 每次 NL 解析时，相关 README.md 注入 prompt，帮助 AI 理解分类语义和归类规则
- **给用户看** — 打开文件夹就能看到这个分类的说明，理解系统如何组织数据
- **自动生成** — AI 创建新分类时自动生成 README.md，用户也可以手动编辑调整

## 模块设计

### 1. QQ 接入层

- Express 服务接收 NapCatQQ HTTP 回调（端口 3456）
- HTTP 客户端调用 NapCatQQ API `send_msg` 发送消息
- 多用户隔离：所有操作按 `user_id` 隔离，每个用户拥有独立的 `data/{userId}/` 目录
- 白名单：环境变量 `QQ_WHITELIST`，逗号分隔的 QQ 号列表

### 2. 消息路由器

**规则预分类（调用 AI 前先做规则匹配，命中则作为 hint 注入 prompt）：**

| 用户输入特征 | 预分类 intent |
|-------------|---------------|
| 包含 "帮我记"、"添加"、"收藏"、"记录" | create |
| 包含 "有什么"、"查一下"、"列出" | query |
| 包含 "看完了"、"完成了"、"做完了"、"吃完了" | update |
| 包含 "删掉"、"删除" | delete |
| 包含 "无聊"、"没意思"、"不知道干嘛" | recommend (boredom) |
| 包含 "吃啥"、"吃什么"、"饿" | recommend (hungry) |
| 包含 "想学"、"学点"、"学习" | recommend (learn) |
| 不匹配任何规则 | null → 全量 AI 解析 |

**上下文管理：** 每用户环形缓冲区保留最近 3 条消息，注入 NL Parser 解决"第三个"等省略引用。

### 3. NL 解析模块

- **模型：** claude-3-5-haiku（意图分类 + 实体提取，性价比高）
- **调用方式：** 无状态单次调用
- **重试策略：** JSON 解析失败时重试一次，第二次仍失败返回 `intent: "unknown"` 兜底

#### 提示词分层设计

提示词分为两层：**缓存层**和**动态层**。

**缓存层（启动时写入一次，走 Claude prompt caching，后续调用不重复计费）：**

| 内容 | 说明 |
|------|------|
| 系统角色定义 | "你是一个个人AI管家的意图解析器..." |
| 输出 JSON Schema | 完整的返回格式定义 + 各字段含义 |
| Few-shot 示例 | 10-15 个典型交互示例（create/query/update/recommend/feedback 各 2-3 个） |
| 交互原则 | 少问多猜、不啰嗦、有温度但不油腻、场景优先 |
| 字段说明 | 编号/兴趣/截止/提醒/重复 等字段的含义和值格式 |

**动态层（每次请求按需注入）：**

| 内容 | 说明 | 触发条件 |
|------|------|----------|
| 文件系统树 | 当前用户 data/ 目录结构（文件夹+.md列表） | 每次请求 |
| 相关 README.md | 与用户消息相关的分类 README 内容 | 按需（场景推荐时注入相关分类，创建时注入候选分类） |
| 预分类 hint | 规则预分类的结果 | 规则命中时 |
| 最近对话上下文 | 最近 3 条消息 | 每次请求 |
| 用户当前消息 | 需要解析的原始文本 | 每次请求 |

**README.md 注入策略：**

```
1. 场景推荐（"好无聊"）
   → 注入 SCENE_FOLDERS["boredom"] 对应分类的 README.md
   → 如：注入 娱乐/README.md

2. 创建条目（"帮我记 runningman"）
   → 注入所有一级分类的 README.md（帮助 AI 选择放哪个分类）
   → 如果 AI 不确定，一级分类太多时只注入目录名列表，AI 初步判断后再按需注入

3. 更新/查询
   → 注入用户最近操作过的分类的 README.md
   → 如果模糊搜索跨多个分类，注入所有匹配分类的 README.md
```

**完整 Prompt 组装流程：**

```
启动时:
  → 加载 system-prompt.md 模板
  → 发送给 Claude API，标记为 prompt cache
  → 缓存写入成功，后续调用使用 cache_id

每次消息到达:
  → 规则预分类 → 得到 hint
  → 根据 intent hint 决定注入哪些 README.md
  → 读取文件系统树（从内存索引获取）
  → 拼装: [cached_system_prompt] + [动态注入内容] + [用户消息]
  → 发送给 Claude API
  → 解析返回 JSON
```

**返回 JSON 格式：**

```json
{
  "intent": "create|query|update|delete|recommend|feedback|unknown",
  "confidence": 0.95,
  "folderPath": "娱乐/综艺",
  "fileName": "综艺",
  "entry": {
    "title": "Running Man",
    "url": "https://xxx",
    "note": null,
    "deadline": null,
    "remind": null,
    "repeat": null,
    "interest": 80,
    "status": "想看",
    "progress": null,
    "importance": null
  },
  "target": {
    "title": "runningman",
    "newStatus": "已看",
    "interestDelta": -80
  },
  "scene": "boredom|hungry|learn",
  "responseHint": "已添加 Running Man 到娱乐/综艺"
}
```

### 4. 文件系统引擎

核心模块，负责所有文件 I/O 和内存索引同步。

```
核心方法：
  scanAll(): Index                           // 启动时全量扫描
  ensureFolder(folderPath): void             // 确保目录存在
  findEntry(query: FuzzyQuery): EntryIndex   // 按标题模糊匹配
  addEntry(folderPath, fileName, entry): EntryIndex
  updateEntry(id, changes): EntryIndex
  deleteEntry(id): void
  getReminders(): EntryIndex[]               // 获取所有待提醒条目
  getByFolder(folderPath): EntryIndex[]      // 获取某分类下所有条目
```

### 5. 推荐引擎

**打分公式：** `score = interest * 0.6 + freshness * 0.2 + variety * 0.2`

**场景 → 文件夹映射：**

```typescript
const SCENE_FOLDERS = {
  boredom: ['娱乐'],           // 推荐 娱乐/ 下所有条目
  hungry:  ['美食'],           // 推荐 美食/ 下所有条目
  learn:   ['学习', '工作'],   // 推荐 学习/ 和 工作/ 下条目
};
```

**去重：** 30 分钟内已推荐条目不再出现
**过滤：** statusChar='x' 或状态为已消费 → 不推荐

### 6. 兴趣权重

| 触发 | delta | 说明 |
|------|:-----:|------|
| 新建条目 | 初始 60 | AI 推测后赋值 |
| 用户明确喜欢 | +25 | 显式正面反馈 |
| 用户明确不喜欢 | -40 | 显式负面反馈 |
| 已消费 | -80 | 看完/吃完后大幅降低 |
| 想多看同类 | +15 | 连带提升 |
| 每日衰减 | -1/天 | 超过 30 天无交互后开始 |

### 7. 定时调度器

| 任务 | 间隔 | 说明 |
|------|:----:|------|
| 提醒检查 | 15s | 遍历内存索引中 `remindAt <= now() AND !reminded` 的条目 |
| 周期性条目生成 | 5min | 检查 repeatRule，到期生成新实例 |
| 过期检测 | 1h | deadline 已过未处理 → 主动询问 |
| 兴趣衰减 | 24h | 超过 30 天无交互条目每日 -1 |
| 每日汇总 | 09:00 | cron 推送当日待办（遍历所有日程表条目） |

## 关键数据流

### 场景一："runningman 看完了"

```
用户 → NapCatQQ → Express → 路由器(预分类:update)
  → NL解析(Claude)
  → 返回 {intent:"update", folderPath:"娱乐/综艺", fileName:"综艺",
           target:{title:"runningman", newStatus:"已看", interestDelta:-80}}

  → UpdateHandler:
     1. 内存索引中模糊匹配 "runningman"，找到条目 编号=rm-001
     2. 如果 H2 "已看" 不存在 → 在文件末尾追加 `## 已看`
     3. 修改 data/娱乐/综艺.md：
        - 旧行: `- [ ] [Running Man](https://xxx)  编号：rm-001  兴趣：高`
        - 新行: `- [x] [Running Man](https://xxx)  编号：rm-001  兴趣：低  更新：2026-05-28`
        - 移动到 `## 已看` 节下
     4. 更新内存索引: statusChar='x', customStatus='已看', interest=20
  → sendMessage("✅ 已标记")
```

### 场景二："好无聊"

```
用户 → 路由器(预分类:recommend+boredom) → NL解析确认

  → RecommendHandler:
     1. SCENE_FOLDERS["boredom"] → ["娱乐"]
     2. 内存索引中: folderPath 以 "娱乐" 开头 AND interest>=30 AND statusChar NOT IN ('x','-')
     3. 打分排序 → top 3
     4. 构建回复 "🎬 要不看看这些：\n1. Running Man（你在追的综艺）\n..."
  → sendMessage(回复)
```

### 场景三：定时提醒触发

```
Scheduler(15s) → 遍历 index.reminders 筛选 remindAt<=now() AND !reminded
  → 逐条: sendMessage("⏰ 5分钟后：开会讨论方案")
  → 更新内存索引: reminded=true
  → 如有 repeatRule: 计算下一次 remindAt, 更新内存索引 + 写回 .md 文件
```

### 场景四：用户新建条目，AI 自动建目录

```
用户: "帮我记个菜谱，宫保鸡丁的做法"

  → NL解析: {intent:"create", folderPath:"美食/菜谱", fileName:"菜谱",
              entry:{title:"宫保鸡丁", note:"做法...", status:"想做"}}

  → CreateHandler:
     1. fileEngine.ensureFolder("美食")    // data/美食/ 已存在跳过
     2. fileEngine.ensureFolder("美食/菜谱") // 不存在 → 创建 data/美食/菜谱/
     3. 检查 data/美食/菜谱/菜谱.md 是否存在 → 不存在 → 创建新文件
     4. 写入条目到 菜谱.md
     5. 更新内存索引
  → sendMessage("✅ 已添加「宫保鸡丁」到美食/菜谱")
```

## 关键设计决策

| 决策 | 选择 | 理由 |
|------|------|------|
| 数据存储 | **纯文件系统**（文件夹=分类，.md=表） | 零依赖，人类可直接浏览编辑，树状结构天然表达分类层级 |
| 查询加速 | **内存索引**（启动时解析全部 .md 驻留内存） | 个人级数据量（数百条），内存索引足够快，无需外部数据库 |
| 条目 ID | 短 UUID + title-hash 回退 | UUID 全局唯一，hash 对手动添加友好 |
| NL 模型 | Haiku（主力） | 意图分类 + 实体提取不需要强推理，性价比高 |
| LLM 状态 | 无状态调用 + 上下文注入 | 避免会话污染，可靠可控 |
| 推荐算法 | 规则计算 + AI 兜底 | 规则可解释、零延迟，AI 仅未知场景 fallback |
| 多用户隔离 | `data/{userId}/` 目录隔离 | 天然文件系统隔离，无需在代码中过滤 |
| 定时器 | setInterval 多粒度轮询 + node-cron 准点 | 15s 轮询提醒够用，每日汇总 cron 准点 |

## 技术栈

| 层 | 方案 |
|---|---|
| 语言 | Node.js + TypeScript |
| QQ 协议 | NapCatQQ（HTTP 回调 + HTTP API） |
| NL 解析 | Claude API（Haiku，单次调用） |
| 存储 | 文件系统（`data/` 目录树 + 内存索引） |
| 调度 | Node.js setInterval + node-cron |
| 部署 | PC 常驻进程，pm2 守护 |

## 安全

- 仅白名单 QQ 号可用，其余消息静默忽略
- QQ 消息内容不入日志（隐私）
- Claude API key 存环境变量，不进代码仓库
