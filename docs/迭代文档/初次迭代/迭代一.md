## QQ 接入架构

最终采用 **反向 WebSocket + HTTP API** 模式：

```
QQ 服务器 ←→ NapCatQQ  ←HTTP(3000)→  Bot 发消息
                         ←WS→  3456  Bot 收消息（反向，NapCat 主动连接）
```

| 方向 | 协议 | 端口 | 说明 |
|------|------|:----:|------|
| Bot → NapCat（发消息） | HTTP POST | 3000 | 调 `/send_private_msg` 等 API |
| NapCat → Bot（收消息） | WebSocket | 3456 | 反向连接，NapCat 作为 WS 客户端连到 Bot |

**NapCat 网络配置页需要两条：**
1. HTTP 服务 → `127.0.0.1:3000`
2. WebSocket 客户端 → `ws://127.0.0.1:3456/ws`

## 数据流

```
用户 QQ 发消息
  → NapCat 接收到消息
    → WebSocket 推送到 Bot（3456/ws）
      → handleEvent() 解析 OneBot v11 事件
        → 白名单过滤
        → routeMessage()
          → 规则预分类（7条正则规则）
          → DeepSeek NL 解析（system prompt + 动态层）
          → action-router 分发意图
        → 返回回复文本
    → sendMessage() HTTP POST 到 NapCat API（3000）
  → NapCat 通过 QQ 协议发送回复
用户 QQ 收到回复
```

## 调试记录

### DeepSeek API 调用
- 使用 `openai` SDK，`baseURL` 设为 `https://api.deepseek.com/v1`（SDK 会自动拼 `/chat/completions`）
- NL 解析测试脚本 `test-nlp.ts`，5 条典型消息全部正确分类

### NapCat 接入踩坑
1. **消息上报**：新版 NapCat WebUI 没有 HTTP 消息上报入口 → 改用反向 WebSocket
2. **Token 验证**：Authorization Header 方式无效（`Bearer` / `Token` 都不行）→ 改为 URL 查询参数 `?access_token=xxx`
3. **WebSocket 方向**：正向连接（Bot → NapCat）收不到事件 → 改为反向（NapCat → Bot）

## 关键设计决策

| 决策 | 选择 | 理由 |
|------|------|------|
| LLM SDK | `openai` npm 包 | DeepSeek API 完全兼容 OpenAI 格式 |
| NL 模型 | `deepseek-chat` | 中文能力强，性价比高 |
| 收消息 | 反向 WebSocket | NapCat v4.x 无 HTTP 回调入口，反向 WS 可用 |
| 发消息 | HTTP POST（原生 `http` 模块） | 调用本机 NapCat API，无需额外依赖 |
| Token 传递 | URL 查询参数 `?access_token=` | Header 方式无效，query param 可用 |
| Prompt 架构 | 缓存层 + 动态层 | 便于维护，后续可加真实文件树注入 |
| 预分类 | 7 条正则规则 | 减少不必要的 AI 调用 |
| 日志 | ANSI 颜色 + 时间 | 按级别着色，纯时间格式更紧凑 |

## 预分类规则

| 正则 | intent | scene |
|------|--------|-------|
| `帮我记\|添加\|收藏\|记录\|记一下\|帮我存` | create | - |
| `有什么\|查一下\|列出\|找一下\|哪些\|搜索` | query | - |
| `看完了\|完成了\|做完了\|吃完了\|买完了` | update | - |
| `删掉\|删除\|去掉\|移除` | delete | - |
| `无聊\|没意思\|不知道干嘛\|不知道看什么` | recommend | boredom |
| `吃啥\|吃什么\|饿了\|想吃\|推荐.*吃` | recommend | hungry |
| `想学\|学点\|学习\|推荐.*学\|学什么` | recommend | learn |

## 环境变量

| 变量 | 说明 | 必填 |
|------|------|:----:|
| `DEEPSEEK_API_KEY` | DeepSeek API Key | ✅ |
| `DEEPSEEK_BASE_URL` | API 地址，默认 `https://api.deepseek.com/v1` | - |
| `DEEPSEEK_MODEL` | 模型名，默认 `deepseek-chat` | - |
| `QQ_WHITELIST` | 白名单 QQ 号，逗号分隔 | ✅ |
| `PORT` | Bot 服务端口，默认 3456 | - |
| `NAPCAT_TOKEN` | NapCat Access Token | ✅ |
| `NAPCAT_BASE_URL` | NapCat HTTP API，默认 `http://127.0.0.1:3000` | - |

## 启动方式

**一键启动：** 双击 `start.bat`（同时开 NapCatQQ 和 Bot 两个终端窗口）

**手动启动：**
```bash
npm run dev      # tsx watch 热重载
npm run build    # tsc 编译
npm start        # 生产启动
```

**独立测试 NL 解析：**
```bash
npx tsx src/test-nlp.ts
```
